* Overview

Modular configuration targeting Emacs 30+. Packages managed by [[https://github.com/progfolio/elpaca][Elpaca]].
Entry point is =init.el=, which loads each =init-*.el= shard in order.

* Issues and Fixes

** RESOLVED: claude-code-ide runs claude inside the =vexxed-dev= podman container

The vexxed repo moved from a Toolbox dev env to a native podman devcontainer.
Claude runs *inside* the =vexxed-dev= container (started by =sandbox/dev.sh=),
driven by a host wrapper that =init-ai.el= points =claude-code-ide-cli-path= at:

#+begin_src shell
# ~/.local/bin/claude-container
exec podman exec -it -w "$PWD" -e HOME=/home/dev \
  -e CLAUDE_CODE_SSE_PORT -e ENABLE_IDE_INTEGRATION \
  -e TERM_PROGRAM -e FORCE_CODE_TERMINAL -e CLAUDE_CODE_NO_FLICKER \
  vexxed-dev claude "$@"
#+end_src

Three things make the MCP integration work end-to-end:
- *Loopback parity:* claude-code-ide's MCP WebSocket server binds
  =127.0.0.1:<port>= on the host. =sandbox/dev.sh= runs =vexxed-dev= with
  =--network=host= so the in-container CLI can reach it. The wrapper forwards
  =CLAUDE_CODE_SSE_PORT= (the lockfile has no auth token, so the env var alone
  is enough).
- *Path parity:* =sandbox/dev.sh= mirror-mounts the repo at its host path
  (=-v "$ROOT":"$ROOT"=) in addition to =/work=. claude-code-ide's MCP file
  ops =find-file= claude's literal paths with no container/TRAMP translation,
  so claude (cwd =/home/jtreddev/vexxed= via the wrapper's =-w "$PWD"=) and the
  local Emacs buffers share one path namespace. Open the project *locally*
  (=C-c v= → =my/vexxed=) for this workflow; eglot uses the host rust-analyzer.
- *Auth:* =sandbox/dev.sh= mounts =~/.claude= into the container so the CLI is
  logged in.

Start the container first (=sandbox/dev.sh=); the wrapper prints a clear
message and exits if =vexxed-dev= isn't running. Use =C-c V= (=my/vexxed-tramp=,
=/podman:vexxed-dev:/work/=) only for *in-container* eglot/compile — not the
Claude workflow, since its =/work= paths don't line up with the wrapper.

** MINOR: =custom.el= is declared but never loaded

=init.el= sets =custom-file= but does not call =(load custom-file 'noerror)=.
This means:
- =custom-set-variables= written by =M-x customize= survive on disk but are
  not applied on startup.
- The =safe-local-variable-values= entry (which marks the podman =cli-path=
  safe) is not loaded, so Emacs re-prompts each session.

*Fix:* add one line to =init.el= after setting =custom-file=:

#+begin_src emacs-lisp
(setq custom-file (expand-file-name "custom.el" user-emacs-directory))
(load custom-file 'noerror)   ; ← add this
#+end_src

** VESTIGIAL: =init-cm.el= — Windows build-tool, not loaded

=init-cm.el= loads =cm= and =cm-hide= from =site-lisp/emacs/= and references
Windows executables (=_cm.exe=, =msdev=, =link.exe=). It is not in
=my/packages= so it causes no startup error, but it is dead weight.
Safe to delete.

** VESTIGIAL: =init-org.el= — orphaned OneDrive path, not loaded

=init-org.el= sets:
#+begin_src emacs-lisp
(setq org-agenda-files "~/../../OneDrive - Kimball International Inc/Org-Mode/agenda")
#+end_src
This Windows path does not exist on Linux. The file is not in =my/packages=
so org-agenda currently has no agenda files configured and no keybindings.

*Fix options:*
1. Add ="org"= to =my/packages= and update the path to a valid Linux location.
2. Inline minimal org settings in =init.el= if agenda is not needed.

** INFO: =my/claude-watch-plans= — works correctly

=init-ai.el= sets a =file-notify= watcher on =~/.claude/plans/= and
auto-displays new/changed =.md= plans in a right side window. The directory
exists and contains plans, so this fires correctly.

If the directory were absent, =file-notify-add-watch= would error during
=:config= evaluation and prevent =claude-code-ide= from loading. Guard it
if you ever move the plans dir:
#+begin_src emacs-lisp
(when (file-directory-p (expand-file-name "~/.claude/plans/"))
  (my/claude-watch-plans))
#+end_src

* Claude Code IDE Setup

** How it works

=claude-code-ide= starts the Claude CLI inside a =vterm= terminal buffer and
wires it to an in-process MCP server. Emacs exposes tools to Claude: xref
(LSP go-to-definition/references), tree-sitter, imenu, Flycheck/Flymake
diagnostics, diff viewer, project navigation. Claude drives the editor; the
diff viewer shows proposed changes inline.

#+begin_example
Emacs (MCP server on 127.0.0.1:<random port>)
   └── vterm terminal
         └── claude-container  →  podman exec … vexxed-dev claude
               └── calls back into Emacs via MCP (vexxed-dev --network=host)
#+end_example

** Prerequisites

#+begin_src sh

# ANTHROPIC_API_KEY must be set for gptel; claude-code-ide uses login auth
#+end_src

** Vexxed project integration

The =.dir-locals.el= in =~/vexxed= configures rust-analyzer for the project:

#+begin_src emacs-lisp
(rust-ts-mode
 . ((eglot-workspace-configuration
     . (:rust-analyzer
        (:procMacro (:enable t)
         :cargo (:buildScripts (:enable t))
         :check (:command "clippy"))))))
#+end_src

=M-x eglot= (or auto-started by =rustic=) picks this up. =M-g s= searches
workspace symbols via =consult-eglot=.

** TRAMP / container workflow (when container is running)

#+begin_src emacs-lisp
C-c v    ;; my/vexxed → project-switch-project into podman:vexxed:/home/jtreddev/vexxed/
          ;; Once inside, eglot/compile/shell all route into the container

The TRAMP config in =init-tramp.el= sets =tramp-histfile-override nil= to
prevent connection failures when the container's =$HOME= has no =.tramp_history=
